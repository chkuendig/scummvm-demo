# Emscripten 6.0.13 upgrade

Source and demo workflow pins now target 6.0.13 (released on 2026-10-19). URL reload is also folded into the existing JavaScript/browser cleanup commit; the branch regrouping does not change the integration source tested by this run. The source bump is folded into the existing `upstream/emscripten-update-cleanup` SDK commit; dependent review branches are reparented and all commit limits still hold. The demo source pin is `9e52e845659e3ec37112c5ae37cd52a2aaa44aa3`. The [full validation build](https://github.com/chkuendig/scummvm-demo/actions/runs/39426597295) was dispatched from demo commit `ddc4aeccde6fc2f0bdd5c8acc7fb543a93dd234b` with `deploy=false`. The full build passed. Game synchronization, cloud deployment and demo deployment were all skipped. The [deployment run](https://github.com/chkuendig/scummvm-demo/actions/runs/39470229200) subsequently completed successfully. The live build reports SDK 6.0.13 and the expected consolidated source and eight branch heads. Chromium launcher/HTTP browsing, Grim and Penumbra startup and touch smoke checks passed. Physical-device gameplay feel and Safari/iOS remain untested.

A clean local SDK install built SDL 3.4.2, FreeType 2.14.3 and libpng 1.6.59, linked them with Asyncify, and ran a library-version smoke program using SDK Node 24.19.0. During the initial SDK upgrade, the generated-JavaScript patches matched two silence callbacks, one recording callback and one playback callback; applying them again was idempotent. Those patches have subsequently been removed from the prepared source after testing the normal audio path without them. No SDL3 experimental warning or `FS.filesystems` reference appeared in that generated glue. The later unpatched Chromium checks covered active playback and simulated blocked autoplay during HTTP browsing without errors. Physical iOS behavior and recorder replay remain untested in this review refresh.

The workflow now supports `workflow_dispatch` with `deploy=false`: build the full configured engine set, save an SDK validation artifact, and skip game synchronization and both publishing jobs. SDK, dependencies, configure and object caches include the SDK version. Build provenance records `emsdkVersion`. The workflow passes actionlint 1.7.12.

The [6.0.13 release notes](https://github.com/emscripten-core/emscripten/releases/tag/6.0.13) record libpng 1.6.58 → 1.6.59 and removal of the undocumented `FS.filesystems` object. The [SDK changelog](https://github.com/emscripten-core/emscripten/blob/6.0.13/ChangeLog.md) places SDL3's non-experimental status in 6.0.10 and FreeType 2.14.3 in 6.0.7, so both were already included in the previous 6.0.11 pin. Verify the actual port versions during the upgrade rather than treating those as new 6.0.13 changes.

1. Audit the browser libraries and generated glue for removed APIs, especially `FS.filesystems`. Use the exported filesystem symbols directly. The current port source has no `FS.filesystems` references; verify the generated build and dependencies too. Keep the existing `FS.stat` migration and persistent IDBFS behavior.
2. Update the default SDK version in `dists/emscripten/build.sh` and `EMSDK_VERSION` in the demo's `.github/workflows/main.yml` together. Check documentation and cache keys for version-specific assumptions. Keep wildcard plugin Asyncify imports.
3. Inspect 6.0.13's SDL3 audio glue against the existing Asyncify callback guards. Check autoplay-blocked silence, active playback and recording. Update or retire guard patterns only after checking the new callbacks; do not restore `test-asyncify-audio-guard.sh` or the obsolete import-list generator.
4. Build the main module, every enabled dependency and all dynamic plugins from clean caches with the same SDK. Emscripten does not promise ABI compatibility between SDK versions. Do not mix 6.0.11 archives or plugins into a 6.0.13 build. Start with a small configuration, then run the existing full all-engine demo configuration.
5. Check the updated FreeType/libpng ports through CJK/font rendering, GUI themes, PNG decoding and browser printing/export. Verify the SDL3 build emits no experimental-port warning.
6. Exercise HTTP range reads and cache eviction, directory browsing, drag-and-drop/ROM import, persistent settings/save reload, Wasm progress and URL-fragment launches. Exercise active audio while opening the file browser and suspending for streamed reads. Run the existing recorder/replay check and native input tests.
7. Check WebGL2 startup, the opaque canvas/OSD/touch overlays and HPL1/Grim startup on Chromium and Safari/iOS where available. Retain clear distinctions between browser automation and physical-device gameplay checks.
8. Deploy only the validated integration, record the SDK and source/branch provenance, and verify the live build information. Preserve the current 6.0.11 deployment as the rollback reference until the new browser checks pass.
